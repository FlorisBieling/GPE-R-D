Step 6: Control maps and shader texture blending

Final terrain appearance

A biome enum can identify one dominant biome, but it cannot describe a gradual transition. Control maps solve that problem by storing several texture weights at every terrain coordinate.

Each channel stores a number between 0 and 1. After normalization, all active weights add up to approximately 1. The shader samples the two maps and multiplies each terrain texture by its corresponding channel. This is why one pixel can contain, for example, 70% plains and 30% forest instead of having to choose one enum value.

How the weights are created

float weight = SmoothRangeWeight(noisyHeight, biome.minHeight, biome.maxHeight, softness)
    * SmoothRangeWeight(temperature, biome.minTemperature, biome.maxTemperature, softness)
    * SmoothRangeWeight(moisture, biome.minMoisture, biome.maxMoisture, softness);

A biome only receives a strong weight when all three input values are close to its configured ranges. biomeBlendSoftness controls the width of the transitions. Boundary noise offsets the local height, while patch noise introduces subtle variation inside transition areas so borders do not look mathematically straight.

Interactive control-map weights

Water is handled differently

In the current generator, a selected water biome immediately receives a water weight of 1. This prevents nearby land textures from bleeding into water. All non-water terrain uses the smooth multi-biome weighting process.

Why one biome enum is not enough

An enum is still useful for logic, but not sufficient for rendering. The biome index answers “which biome is dominant?” The control maps answer “how much of every texture should be visible here?” Keeping those responsibilities separate makes both systems clearer.

Why control maps were chosen

Compared with one biome enum

Several textures can contribute to one pixel

A dominant enum can only choose one result. Control-map weights support smooth plains-to-forest or mountain-to-snow transitions.

Compared with splitting the mesh by material

The geometry stays simple

Chunks do not need extra submeshes or material boundaries. The same mesh can display any biome combination through two compact RGBA maps.

Compared with storing weights in vertices

Texture resolution is independent from mesh LOD

The blend can remain detailed even when a distant chunk uses fewer vertices, and the shader receives the same channel layout for every LOD.

Optimisation opportunity

Profile the active texture count

Two control maps are a compact interface, but the final shader still samples several source textures. Optimisation is only necessary when profiling shows this is a real GPU bottleneck.
