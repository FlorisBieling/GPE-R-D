Step 7: Custom URP shader and Asset Store texture workflow

GPU rendering

The terrain does not use one ready-made material per biome. The source textures came from the Yughues Free Ground Materials package on the Unity Asset Store. Selected texture sets were combined in one custom URP shader so every chunk can use the same material while the control maps determine the local result.

Why one custom shader was chosen

Several approaches were possible. Separate materials per biome would require submeshes or hard material borders. Shader Graph could provide a visual workflow, but a seven-layer blend with custom control-map channels becomes large and harder to document precisely. A custom HLSL shader was chosen because it gives direct control over the channel layout, world-space sampling and lighting while keeping every chunk on one material system.

Compared with separate materials

One material can render the complete terrain

The mesh does not need to be divided by biome, and transitions are handled per pixel rather than at geometry boundaries.

Compared with local mesh UVs

World-space sampling keeps chunks visually continuous

Using positionWS.xz means the texture pattern continues across neighbouring chunks instead of restarting at every local origin.

Compared with a large Shader Graph

The blending rules are explicit and reusable

The relationship between control-map channels and biome textures is visible in code, easy to version and straightforward to explain in the research documentation.

Future refinement

Optimise only after measuring the target platform

Custom HLSL gives full control, but also makes the project responsible for later improvements such as reducing inactive texture samples or adding slope-aware mapping.

Texture sets used in the material

Each biome uses an albedo texture (_d), a normal map (_n) and a specular map (_s). The editor utility searches for the exact Asset Store texture names and assigns them to the custom material.

How the shader combines the textures

float waterWeight = controlA.r;
float beachWeight = controlA.g;
float plainsWeight = controlA.b;
float forestWeight = controlA.a;
float desertWeight = controlB.r;
float mountainWeight = controlB.g;
float snowWeight = controlB.b;

albedo += SampleAlbedo(_WaterTex, waterUV) * waterWeight;
albedo += SampleAlbedo(_BeachTex, beachUV) * beachWeight;
// The same pattern continues for plains, forest, desert, mountain and snow.
albedo /= totalWeight;

The same normalized weights are applied to albedo, tangent-space normal and specular samples. The resulting normal is converted to world space, then the shader calculates main-light diffuse, a custom specular highlight, spherical-harmonic ambient light, shadows and fog.

Why albedo, normal and specular maps are all used

Albedo

Provides the visible base color and large surface pattern.

Normal

Adds small lighting detail without adding more terrain vertices.

Specular

Controls where the custom highlight is stronger or weaker.

Per-biome scale

Lets every source texture use a different world-space tiling frequency.

Technical strengths and the next useful improvement

Rendering strength

Albedo, normal and specular use the same biome weights

Every material property changes together across biome boundaries, so transitions remain visually consistent instead of blending only the base color.

URP integration

Lighting, shadows, ambient light and fog are included

The shader is integrated into the scene rather than acting as an unlit texture mixer, which makes the generated terrain respond to the world lighting.

Implementation quality

Material values use one UnityPerMaterial CBUFFER

This follows the structure expected by SRP Batcher-compatible custom URP shaders and keeps material properties organised.

Most relevant future improvement

Reduce sampling cost and improve steep slopes when needed

The current shader samples all seven albedo, normal and specular sets and uses XZ planar mapping. Profiling may justify dominant-layer shortcuts, texture arrays or triplanar mapping; the unused _ColorMap property can then be removed or deliberately integrated.

How texture assignment works

  1. Import Yughues Free Ground Materials from the Unity Asset Store into your own project.
  2. Create or select the material that uses Custom/ProceduralBiomeTexturesURP.
  3. Place AssignExactYFGMBiomeTextures_Final.cs in an Editor folder.
  4. Run Tools → Procedural Terrain → Assign Final YFGM Textures.
  5. The utility finds textures by exact asset name and fills the shader properties.
