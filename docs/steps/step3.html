Step 3: Interpreting height and building a mesh

From values to geometry

A normalized height map becomes useful when each value is converted into a vertex height. The same values can also be divided into readable regions such as water, coast, land and mountain.

Height ranges are the first classification layer

Earlier versions used fixed color thresholds. The current biome system is more flexible, but the principle is still important: height is one of the three ranges every biome must satisfy. Low height can represent water, middle values can represent plains or forest, and high values can represent mountain or snow.

Mesh generation

meshData.vertices[vertexIndex] = new Vector3(
    topLeftX + x,
    heightCurve.Evaluate(heightMap[x, y]) * heightMultiplier,
    topLeftZ - y
);

The x and z values place vertices on a regular grid. The y value comes from the height map after an AnimationCurve and multiplier are applied. The curve is useful because it can flatten low terrain while making high values steeper without regenerating the noise itself.

Why the chunk size is 241

The mesh generator skips vertices based on the selected LOD. A chunk size of 241 means the usable interval is 240, which is divisible by several simplification increments. That allows multiple LOD meshes to line up with the same chunk boundaries.

Why a generated height-field mesh was chosen

Compared with Unity Terrain

The project keeps direct control over chunk meshes

Custom meshes fit naturally with the existing chunk, LOD and threading pipeline and make every generation step visible in code.

Compared with voxel terrain

It is simpler and cheaper for an outdoor landscape

A regular height field needs one height per x/z coordinate, which is efficient for hills, plains, mountains and large viewing distances.

Compared with a fixed imported mesh

It can be regenerated from the seed

The world does not need to be modelled or stored in advance, and the same source data can produce several LOD versions.

When another option would be better

Voxels or volumetric meshes are needed for caves

The chosen height-field method is ideal for the current surface world. A game centred on tunnels, overhangs or destructible terrain would justify a more complex geometry representation.
