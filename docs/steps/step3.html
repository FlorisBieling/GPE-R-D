Step 3: From Noise to Terrain Shapes

Goal of This Step

The previous steps focused on generating structured noise and controlling its appearance through parameters such as scale, octaves, persistence, and lacunarity. At that point, the system could already produce useful data, but that data was still abstract. It existed only as grayscale values.

This step mainly addresses sub question 2: how Perlin noise can be used to generate a structured terrain or biome map. The first part of that answer is learning how to interpret raw noise values as terrain categories.

Why This Step Was Needed

A grayscale noise map is useful for understanding the internal structure of the data, but it is not yet very meaningful as terrain. A player or developer cannot immediately read black, gray, and white values as ocean, land, or mountain unless those values are translated into terrain types.

That is why this step is necessary. Instead of treating the generated values as abstract intensity, the system now starts interpreting them as height. Once the values are seen as height, they can be divided into ranges that represent different parts of the landscape.

This is an important shift in the project. The noise map is no longer only a mathematical output, but the beginning of an actual terrain model.

Why Thresholds Were Chosen

The simplest and most controllable way to convert height values into terrain categories is by using thresholds. A threshold is a boundary value that determines when one terrain type changes into another.

This method was chosen because it is easy to understand, easy to tune, and works well with procedurally generated data. By adjusting only a few threshold values, the world can quickly become more ocean-heavy, more mountainous, or more land-based.

Other approaches could be used, such as continuous biome blending or more advanced classification systems, but thresholds are a strong first step because they make the data much easier to interpret while keeping the system simple.

How Height Thresholds Work

The noise map contains values between 0 and 1 after normalization. On their own, these values do not yet describe what type of terrain a position should represent. A threshold-based system assigns meaning to those values by splitting them into ranges.

For example, low values can represent water, medium values can represent land, and high values can represent mountains. This means that one single noise map can already be transformed into a readable terrain layout.

In this project, the thresholds are used like this:

- values below 0.35 represent water
- values between 0.35 and 0.42 represent beach
- values between 0.42 and 0.70 represent grass or land
- values above 0.70 represent mountain

These exact values are not fixed rules. They are design choices that can be adjusted depending on the type of world that is needed.

Why This Improves the System

Interpreting noise values as terrain makes the output much more useful. Instead of only seeing a pattern, it becomes possible to understand the generated world as a landscape with recognizable regions.

This also creates a much stronger base for later steps. Once height values are translated into terrain categories, the same information can later be reused for biome systems, mesh generation, and object placement.

How This Works in Unity

In Unity, this is done by looping over every position in the generated map and checking which height range the value belongs to. A color is then assigned based on that range. 

for (int y = 0; y < mapHeight; y++)
{
    for (int x = 0; x < mapWidth; x++)
    {
        float currentHeight = noiseMap[x, y];

        if (currentHeight < 0.35f)
        {
            colorMap[y * mapWidth + x] = Color.blue;
        }
        else if (currentHeight < 0.42f)
        {
            colorMap[y * mapWidth + x] = new Color(0.9f, 0.85f, 0.6f);
        }
        else if (currentHeight < 0.70f)
        {
            colorMap[y * mapWidth + x] = Color.green;
        }
        else
        {
            colorMap[y * mapWidth + x] = Color.gray;
        }
    }
}

What This Code Does

The code checks the height value at every coordinate and compares it to a set of threshold values. Depending on which range the height falls into, a different terrain color is assigned.

This means the map is no longer displayed as raw grayscale data. Instead, the generated values are translated into terrain regions that are much easier to read and reason about.

The thresholds also act as simple control points. Raising the water threshold will increase the amount of ocean, while lowering it will expose more land. In the same way, changing the mountain threshold changes how much of the world is considered high terrain.

This directly contributes to sub question 2, because it shows one of the first practical ways in which Perlin noise can be transformed from raw mathematical data into a structured terrain map.

What This Step Adds to the System

This step transforms the project from procedural pattern generation into procedural terrain interpretation. The generated noise is no longer only a technical output, but becomes a readable landscape made up of water, coast, land, and mountains.

That makes this step a major bridge between sub question 1 and sub question 2. The earlier steps explained how Perlin noise works and how its parameters influence the pattern, while this step shows how those values can be turned into the first structured version of a terrain map.

In the next step, this idea is extended further by adding a second map. Instead of using only height, the system will also use temperature, which makes it possible to create more varied biome types.
