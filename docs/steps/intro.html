Introduction: what the current system actually is

Project overview

This project is a complete procedural-terrain pipeline in which noise generation, biome classification, texture blending, chunk streaming and decoration placement work together. The value of the system is not only that it produces a world, but that each technical choice has a clear role and can be adjusted independently.

Height controls mesh elevation. Temperature and moisture add climate variation. The three values are evaluated against configured biome ranges, while a separate control-map generator calculates smooth texture weights. The custom URP shader then blends albedo, normal and specular textures in world space.

Why the overall architecture is a good fit

Chosen approach

One dataset drives several systems

The same height, temperature and moisture data controls mesh shape, biome logic, texture weights and decoration rules. This avoids systems contradicting each other.

Chosen approach

Gameplay logic and rendering are separated

A dominant biome is useful for rules and object placement, while control-map weights are better for gradual visual transitions. Each representation is used where it is strongest.

Chosen approach

Specialised classes keep the pipeline understandable

Biome selection, control-map generation and decoration placement are separated instead of remaining inside one 1,100-line class. This makes changes easier to test and explain.

Chosen approach

CPU generation and GPU rendering have clear roles

The CPU prepares world data and compact texture weights; the shader handles detailed per-pixel blending. This division keeps the terrain flexible without rebuilding geometry for every visual change.

One logical next refinement

The most useful next step is profiling the complete pipeline on the intended target hardware. That will show whether shader sampling, runtime textures or decoration GameObjects deserve optimisation first, instead of changing parts of the system based only on assumptions.

Research question

How can coherent noise be transformed into a varied, textured and continuously generated Unity world, and which design choices make that pipeline understandable and usable in real time?
