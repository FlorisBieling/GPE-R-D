Step 1: Perlin Noise

Goal of This Step

The first step in this project is to establish a foundation for procedural terrain generation. Before terrain can be shaped, colored, or turned into a 3D world, a structured source of data is needed. This step focuses on generating that data using Perlin noise.

This step mainly addresses sub question 1: what Perlin noise is, and how parameters such as scale influence the generated result. The other parameters, such as octaves, persistence, and lacunarity, are introduced more fully in the next step.

Why Perlin Noise Was Chosen

A procedural terrain system needs values that feel natural and connected. Using completely random numbers for each position would produce harsh and chaotic transitions, which makes the result difficult to interpret as terrain. Mountains, oceans, and plains would appear as disconnected fragments instead of continuous shapes.

Perlin noise is more suitable because nearby positions tend to produce similar values. This creates gradual transitions instead of abrupt jumps. For terrain generation, this is important because height should usually change smoothly across the world rather than randomly from one tile to the next.

Other methods could also be considered. Pure random generation is simple, but it does not create believable terrain. Cellular automata can produce interesting organic patterns, but they are generally more suitable for structures such as caves or local map evolution than for broad continuous terrain. Perlin noise was chosen here because it offers a strong balance between control, readability, and natural-looking variation.

What Perlin Noise Does

Perlin noise generates smooth numerical variation across a 2D space. Each position on the map receives a value, and positions that are close together tend to have related values. Instead of each point behaving independently, the values blend into one another.

In this project, these values are first interpreted as height data. At this stage, they are not yet terrain types or biomes, but they already form the raw structure that later steps will build on.

How Scale Influences the Result

The most important parameter in this first version is scale. Scale determines how stretched or compressed the noise pattern is.

A small scale results in more rapid variation, which makes the map look more detailed and busy. A large scale stretches the noise over a bigger area, which produces broader and smoother shapes. Because of this, scale already has a large impact on whether the result feels rough, soft, zoomed-in, or zoomed-out.

The seed is also included in the demo. The seed does not change how the system works, but it changes which pattern is generated. In other words, scale changes the character of the map, while seed changes the specific variation.

How This Works in Unity

In Unity, this starts with generating a value for each position in a 2D grid. The code below shows the full noise generation method used in the project. Even though this version already contains additional parameters for later expansion, the core idea is still the same: loop through the map and calculate a noise value for each coordinate. 

public static float[,] GenerateNoiseMap(int mapWidth, int mapHeight, int seed, float scale, int octaves, float persistance, float lacunarity, Vector2 offset)
{
    float[,] noiseMap = new float[mapWidth, mapHeight];

    System.Random prng = new System.Random(seed);
    Vector2[] octaveOffsets = new Vector2[octaves];

    float amplitude = 1;
    float frequency = 1;

    for (int i = 0; i < octaves; i++)
    {
        float offsetX = prng.Next(-100000, 100000) + offset.x;
        float offsetY = prng.Next(-100000, 100000) - offset.y;
        octaveOffsets[i] = new Vector2(offsetX, offsetY);

        amplitude *= persistance;
    }

    if (scale <= 0)
    {
        scale = 0.0001f;
    }

    float halfWidth = mapWidth / 2f;
    float halfHeight = mapHeight / 2f;

    for (int y = 0; y < mapHeight; y++)
    {
        for (int x = 0; x < mapWidth; x++)
        {
            amplitude = 1;
            frequency = 1;
            float noiseHeight = 0;

            for (int i = 0; i < octaves; i++)
            {
                float sampleX = (x - halfWidth + octaveOffsets[i].x) / scale * frequency;
                float sampleY = (y - halfHeight + octaveOffsets[i].y) / scale * frequency;

                float perlinValue = Mathf.PerlinNoise(sampleX, sampleY) * 2 - 1;
                noiseHeight += perlinValue * amplitude;

                amplitude *= persistance;
                frequency *= lacunarity;
            }

            noiseMap[x, y] = noiseHeight;
        }
    }

    return noiseMap;
}

What This Code Does

The method creates a two-dimensional array and fills it with noise values. For every x and y position, the code calculates a sample position and uses Unity’s Mathf.PerlinNoise to retrieve a smooth value. That value is then stored in the map.

The most important lines for this step are the sample coordinates: 

float sampleX = (x - halfWidth + octaveOffsets[i].x) / scale * frequency;
float sampleY = (y - halfHeight + octaveOffsets[i].y) / scale * frequency;

These lines determine where the noise function is sampled. The scale value directly affects these coordinates, which is why changing the scale has such a visible effect on the result.

Although the code already contains octaves, persistence, and lacunarity, this first step mainly focuses on the basic idea: one procedural function can be sampled across a grid to produce structured terrain data.

What This Step Adds to the System

This step provides the core data source for the rest of the project. Without a structured height map, later steps such as terrain thresholds, biome generation, and mesh creation would not be possible.

It also shows why Perlin noise is a useful starting point for procedural terrain. It creates smooth, controllable variation and forms a better foundation for large landscapes than purely random generation.

In the next step, the system is expanded by looking at how additional parameters such as octaves, persistence, and lacunarity influence the result, making the terrain more detailed and flexible.
