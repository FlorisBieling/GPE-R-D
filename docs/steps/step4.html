Step 4: Combining Height and Temperature

Goal of This Step

In the previous step, Perlin noise values were interpreted as terrain using height thresholds. This already made it possible to distinguish between water, land, and mountains. However, this approach still had a limitation: areas with the same height always resulted in the same type of terrain.

This step continues answering sub question 2 by extending the system from terrain classification to a more complete biome system. Instead of using only height, an additional data layer is introduced: temperature.

Why Height Alone Was Not Enough

When using only height, the system can only describe vertical structure. This means that all areas at a similar height look the same, regardless of any other environmental factors. For example, all mid-height areas become the same type of land, and all high areas become the same type of mountain.

In reality, terrain is influenced by more than just height. Two areas at the same elevation can look completely different depending on climate conditions such as temperature or moisture. Because of this, a second data layer is needed to introduce variation.

Why Temperature Was Chosen

Temperature was chosen as the second map because it is intuitive and works well together with height. While height determines the shape of the world, temperature determines what kind of environment fits that location.

This allows the system to differentiate between areas that would otherwise be identical. For example, a high area can become a cold snowy biome or a warmer rocky biome, while mid-height terrain can become either lush or dry depending on the temperature value.

Other options, such as moisture, could also be used. However, temperature was chosen as the first extension because it is simple to implement and already introduces a significant increase in variation.

How the Temperature Map Works

The temperature map is generated in the same way as the height map, using Perlin noise. The main difference is that it uses a different seed and a larger scale. This results in broader and more gradual variation across the map.

Using a larger scale ensures that temperature changes more slowly across the world than height. This reflects how climate behaves in reality: temperature zones tend to span larger regions than terrain features.

How Height and Temperature Are Combined

Once both maps are generated, the system reads both values at the same position and uses them together to determine the final biome. Instead of checking only height thresholds, the system now checks combinations of height and temperature ranges.

This creates a two-dimensional classification system, where one axis represents height and the other represents temperature. Each combination corresponds to a different biome.

How This Works in Unity

In Unity, both maps are generated separately using the same noise function. The temperature map uses a different seed and a larger scale. 

float[,] heightMap = Noise.GenerateNoiseMap(
    mapChunkSize,
    mapChunkSize,
    seed,
    noiseScale,
    octaves,
    persistance,
    lacunarity,
    centre + offset,
    normalizeMode
);

float[,] temperatureMap = Noise.GenerateNoiseMap(
    mapChunkSize,
    mapChunkSize,
    seed + 2,
    noiseScale * 5f,
    octaves,
    persistance,
    lacunarity,
    centre + offset,
    normalizeMode
);

After generating both maps, the values are combined when assigning the final color or biome type. 

float currentHeight = heightMap[x, y];
float currentTemperature = temperatureMap[x, y];

colorMap[y * mapChunkSize + x] =
    GetColor(currentHeight, currentTemperature);

What This Code Does

For each position in the map, the system retrieves both the height and temperature values. These values are then passed into a function that determines which biome should be assigned.

This means that the same height value can now result in different biomes, depending on the temperature. Instead of one-dimensional terrain classification, the system now supports more complex and varied results.

This directly contributes to sub question 2, because it shows how multiple Perlin noise maps can be combined to create a structured biome system instead of only a simple terrain map.

What This Step Adds to the System

This step transforms the project from a simple terrain classification system into a more complete biome system. By combining multiple data layers, the world becomes more varied and believable without changing the core generation method.

It also demonstrates an important concept in procedural generation: complex results do not necessarily require completely new algorithms, but can often be achieved by combining multiple simple systems.

In the next step, this data is no longer only visualized in 2D. Instead, it is used to generate an actual 3D world in Unity, where the same data drives terrain meshes, textures, and object placement.
