How to implement in Unity

Goal of This Setup

This section explains how the procedural terrain system can be added to a Unity project. The goal is not only to show the final result, but also to make the system reusable. By following this setup, the generator can be placed into another Unity scene and used to create terrain, biome colors, and biome-based decoration.

The implementation is centered around one empty GameObject in the scene. This object acts as the main controller for the terrain system and holds the scripts that generate the data, preview the terrain, and load chunks around the player.

1. Create the Main Terrain Object

Start by creating an empty GameObject in the Unity hierarchy. This object can be named something like WorldGenerator or TerrainSystem. Attach the following scripts to this object: MapGenerator, MapDisplay, and EndlessTerrain.

MapGenerator is the core of the system. It generates the height map and temperature map, combines them into biome colors, and also prepares the decoration spawn data. The map generation uses Perlin noise, and the final biome result is decided by combining height and temperature values.

MapDisplay is mainly used for testing. It can draw the generated result onto a single mesh or texture in the editor, which makes it useful while tuning settings. It is not required for the actual endless terrain system during gameplay, but it is useful while developing and debugging the generator. :contentReference[oaicite:6]{index=6}

EndlessTerrain is responsible for loading and updating terrain chunks around the viewer. It checks where the viewer is, decides which chunks should be visible, and chooses the correct level of detail for each chunk. :contentReference[oaicite:7]{index=7}

2. Assign the Required References

In the MapDisplay component, assign the mesh or renderer that should be used for previewing the terrain in the editor. This is only needed for testing purposes. The script can draw either a texture or a generated mesh to show the current map result directly in Unity. :contentReference[oaicite:8]{index=8}

In the EndlessTerrain component, assign a Viewer transform. This is usually the player or camera. The system uses this transform to calculate which chunks are close enough to be visible and which level of detail should be used. The visible distance is taken from the configured detail levels. :contentReference[oaicite:9]{index=9}

Also assign the terrain material in EndlessTerrain. This material is applied to the generated chunk meshes so the biome color map can be shown on the terrain.

3. Configure the Map Generator

The MapGenerator component contains the main terrain settings. These include values such as noise scale, octaves, persistence, lacunarity, seed, redistribution power, mesh height multiplier, and the height curve. Together, these values control the shape and variation of the generated world. The generator creates both a height map and a temperature map, where the temperature map uses a different seed and a larger scale so that climate variation changes more gradually across the world.

If Auto Update is enabled, the preview can update directly in the editor while changing values. This is useful while testing settings.

4. Set Up the Height Types

The most important part of the biome setup is the Height Types array. These should always be entered from low to high, meaning from values near 0 up to values near 1. In practice, this means you start with something like oceans, then low land, then higher land, hills, and mountains.

Each height type contains a height value and a list of Biome Types. The generator checks the current height first and then checks the temperature within that height range. This is how the system decides which biome a position belongs to. The biome color returned by the generator is taken directly from that result. :contentReference[oaicite:11]{index=11}

For every biome, you should fill in:

- a Name, used for readability and layer grouping
- a Temperature value, also ordered from low to high within that height type
- a Color, which becomes the terrain color for that biome

This means that one height level can contain multiple biome variations. For example, one land height can become a cold plain, a normal plain, or a warm plain depending on the temperature value.

5. Add Decoration Layers

Each biome can also contain one or more Decoration Layers. These are used to place objects such as trees, rocks, grass, or other environment prefabs. The system first checks which biome is present at a position, then looks at the decoration layers for that biome, and finally decides whether something should spawn there.

In each decoration layer, you can assign one or more prefabs. When the system decides to spawn something in that layer, one of those prefabs is chosen randomly.

The decoration layer settings work as follows:

Name
This is only used for clarity in the inspector and for grouping the spawn cache internally.

Prefabs
This is the list of objects that can spawn in this layer. You can place one prefab here, or multiple prefabs if you want variation.

Spawn Chance
This controls the chance that a valid spawn attempt will actually place an object. Lower values make the layer more sparse.

Noise Scale
This controls how stretched or compressed the decoration noise pattern is. A smaller scale creates more rapid variation, while a larger scale creates broader grouped areas.

Noise Threshold
This is the minimum decoration noise value needed before spawning is allowed. Raising this threshold creates fewer and more clustered spawn areas.

Min Distance
This sets the minimum distance allowed between placed objects in the same layer. It helps prevent objects such as trees from spawning too close together.

Attempts Per Tile
This controls how many spawn attempts are made for each checked tile. Higher values can increase density, but also increase cost.

Sample Interval
This determines how often tiles are checked. For example, a value of 3 means the system only checks every third tile in both directions. This is useful for reducing cost and avoiding excessive object counts. The generator explicitly skips positions that do not match the sample interval. :contentReference[oaicite:13]{index=13}

Random Offset Range
This adds random local position variation so objects do not all appear in the exact center of a tile.

Random Scale Range
This allows spawned prefabs to vary in size between a minimum and maximum value.

Noise Offset
This shifts the decoration noise pattern, making it possible to create a different placement layout without changing the rest of the biome setup.

6. How the World Is Generated at Runtime

When the scene runs, the generator creates map data for chunks around the viewer. Each chunk receives a height map, temperature map, and color map. That data is then used to build a mesh, apply a texture, and prepare decoration spawn positions.

The actual object instantiation is handled later by the terrain chunk logic. Decorations are not all spawned in one frame. Instead, they are instantiated gradually, which helps reduce visible lag spikes during gameplay. :contentReference[oaicite:15]{index=15}
