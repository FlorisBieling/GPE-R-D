Step 8: Procedural snow and biome decorations

Surface variation

The system adds variation after the base biome weights are calculated. Snow receives its own procedural mask, and decoration layers turn biome data into deterministic spawn instructions.

Why the snow line is irregular

A pure height threshold would create a perfectly horizontal border. The current mask samples low-frequency noise and uses it to move the local snow start height up or down. A second noise field subtracts holes from the transition, while the highest terrain gradually becomes fully covered again. 

float localStart = start
    + (lineNoise - 0.5f) * snowLineNoiseHeightInfluence * 2f;

float amount = Mathf.SmoothStep(
    0f,
    1f,
    Mathf.InverseLerp(localStart, localStart + transition, height)
);

return Mathf.Clamp01(
    amount - holeAmount * (1f - Mathf.SmoothStep(end, 1f, height))
);

Decoration layers

Each biome can contain one or more decoration layers. A layer defines available prefabs, spawn chance, noise threshold, spacing, sampling interval, random offset and random scale. The generator does not instantiate objects in the background thread. It only creates plain DecorationSpawnData records.

1. Select biome

Read height, temperature and moisture at the sampled tile.

2. Test layer

Apply sample interval, noise threshold, chance and minimum distance.

3. Store data

Save prefab index, local position, rotation, scale and height value.

4. Instantiate later

EndlessTerrain spawns a limited number of GameObjects per frame.

Why spawning is deterministic

The random generator is seeded from the world seed, chunk position, tile coordinates and layer index. A chunk therefore produces the same decoration layout each time it is generated, while still appearing random.

Why these procedural systems were chosen

Compared with one flat snow threshold

The snow line looks organic while remaining controllable

Line noise moves the boundary and hole noise breaks up the transition, while start and end height still give clear artistic control.

Compared with a hand-painted snow mask

The mask works across an endless seeded world

Every chunk calculates the same result from world coordinates, so no large authored mask has to be stored or aligned.

Compared with spawning objects immediately

Decoration data and Unity object creation are separated

Spawn decisions can be prepared in the background, while deterministic records are instantiated gradually on the main thread.

Future scale improvement

Dense forests may benefit from pooling or GPU instancing

The current GameObject approach is clear and suitable for the prototype. A much larger object count would justify a more specialised rendering strategy.
