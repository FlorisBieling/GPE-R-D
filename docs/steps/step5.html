Step 5: From 2D Data to Unity World Generation

Goal of This Step

In the previous steps, Perlin noise was used to generate structured data and interpret it as terrain and biomes. However, the system was still limited to 2D visualizations. While useful for understanding the data, it did not yet result in an actual game environment.

This step continues answering sub question 2 by showing how the generated data can be applied in Unity to create a 3D world. The noise maps are no longer only displayed, but used to build terrain, textures, and gameplay-relevant systems.

Why This Step Was Needed

A procedural system only becomes useful in practice when it can be applied inside a game engine. Up to this point, the project demonstrated how data could be generated and interpreted, but it did not yet show how that data could be used to construct an actual environment.

This step is important because it transforms the project from a conceptual demonstration into a functional system. The same data that was previously visualized in 2D is now used to generate a 3D world inside Unity.

Reusing the Same Data Across Systems

One of the key design choices in this project is that the same generated data is reused across multiple systems. Instead of generating separate data for each feature, the height and temperature maps act as a shared foundation.

This means that a single dataset can control:

- terrain shape
- biome colors
- object placement
- gameplay rules

This approach was chosen because it keeps the system consistent and makes it easier to extend. Changes in the data automatically affect multiple parts of the world at once.

From Height Map to 3D Mesh

To create an actual terrain, the height map is converted into a mesh. Each value in the map becomes a vertex in 3D space. The x and z coordinates define the position on the ground, while the y coordinate is based on the height value. 

meshData.vertices[vertexIndex] = new Vector3(
    topLeftX + x,
    heightCurve.Evaluate(heightMap[x, y]) * heightMultiplier,
    topLeftZ - y
);

By connecting these vertices with triangles, Unity can render the terrain as a continuous surface. This is the point where the system transitions from data representation to visible geometry.

Applying Biome Data as Textures

The biome system is also applied visually. The combined height and temperature data is converted into a color map, which is then used as a texture on the terrain mesh. 

display.DrawMesh(
    MeshGenerator.GenerateTerrainMesh(
        mapData.heightMap,
        meshHeightMultiplier,
        meshHeightCurve,
        editorPreviewLOD
    ),
    TextureGenerator.TextureFromColorMap(
        mapData.colorMap,
        mapChunkSize,
        mapChunkSize
    )
);

This ensures that the terrain shape and its appearance are both driven by the same procedural data.

Why Chunk-Based Generation Was Introduced

Generating an entire world as a single mesh would quickly become impractical. As the size of the world increases, the number of vertices, calculations, and memory usage grows rapidly.

To solve this, the world is divided into smaller sections called chunks. Each chunk is generated independently and only when needed. 

terrainChunkDictionary.Add(
    viewedChunkCoord,
    new TerrainChunk(
        viewedChunkCoord,
        chunkSize,
        detailLevels,
        transform,
        mapMaterial
    )
);

This approach allows the world to feel continuous while internally being built out of manageable pieces. It also prepares the system for real-time generation, where new chunks can be created as the player moves.

Object Placement Based on Biomes

The generated biome data is also used for object placement. Instead of placing objects randomly, the system first determines which biome is present at a position, and then decides what can spawn there. 

BiomeType biome = GetBiome(currentHeight, currentTemperature);

if (biome.decorationLayers == null || layerIndex >= biome.decorationLayers.Length)
{
    continue;
}

Additional rules can be applied, such as spawn chance, sampling intervals, and distance checks. This makes object placement depend on the generated world, rather than being completely random.

Why This Matters for the Final System

This step is where the procedural system becomes usable as part of a real project. The generated data is no longer only a visualization tool, but a complete foundation for building a world inside Unity.

It also aligns with the goal of creating a reusable system. Because the data drives multiple systems at once, the generator can be integrated into different projects without needing to redesign each component separately.

This makes the system suitable for use as a general tool, for example as a Unity Asset Store package that other developers can use in their own games.

What This Step Adds to the System

This step transforms the project from a data-driven prototype into a full procedural generation pipeline. The same noise-based data is now used to generate terrain meshes, textures, and object placement in Unity.

It also introduces the first signs of performance challenges. Generating meshes, textures, and objects for multiple chunks increases the workload significantly, which leads directly into the next step.

In the next step, the focus shifts to analysing these performance challenges and understanding where the main bottlenecks occur when scaling the system.
