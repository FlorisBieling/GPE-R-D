Step 5: From 2D Data to Unity World Generation

In the previous steps, the generated data was mainly shown as 2D images. That was useful for understanding how height, temperature, and biome selection work, but in an actual Unity project this data is not only used for visualization. It becomes the input for the world generation system itself.

This is an important shift in the project. The map is no longer just a texture or preview image, but a set of values that can be used to build terrain, assign biomes, place decorations, and control gameplay rules.

Using the Same Data for Multiple Systems

In the Unity project, the same generated map data is reused in different ways. The height map is used to define the shape of the terrain, the temperature map helps decide which biome belongs to each position, and the resulting biome data can then be used for textures, decoration placement, and spawn rules.

This means one generated dataset can drive multiple systems at once:

- terrain shape
- biome colors
- decoration placement
- rules for what can spawn where

How This Works in Unity

The map generator creates both a height map and a temperature map. These are then combined into a color map that represents the biome result. 

float[,] heightMap = Noise.GenerateNoiseMap(
    mapChunkSize,
    mapChunkSize,
    seed,
    noiseScale,
    octaves,
    persistance,
    lacunarity,
    centre + offset,
    normalizeMode
);

float[,] temperatureMap = Noise.GenerateNoiseMap(
    mapChunkSize,
    mapChunkSize,
    seed + 2,
    noiseScale * 5f,
    octaves,
    persistance,
    lacunarity,
    centre + offset,
    normalizeMode
);

return new MapData(heightMap, temperatureMap, CombineMaps(heightMap, temperatureMap));

This shows that the project does not generate only one grayscale map. It generates a set of related data layers that can be used throughout the whole generation pipeline.

From Height Map to 3D Mesh

To turn this data into an actual Unity world, the height values are converted into a mesh. Each point in the height map becomes a vertex in 3D space. The x and z coordinates define the position on the ground, while the y coordinate is based on the sampled height value. 

meshData.vertices[vertexIndex] = new Vector3(
    topLeftX + x,
    heightCurve.Evaluate(heightMap[x, y]) * heightMultiplier,
    topLeftZ - y
);

After that, triangles are created between the vertices so Unity can render the surface as terrain. This is the step where the project moves from 2D data into an actual 3D world.

Applying Biome Colors

The generated biome result is also used visually. After the height and temperature data are combined into biome colors, those colors are converted into a texture and applied to the mesh. 

display.DrawMesh(
    MeshGenerator.GenerateTerrainMesh(mapData.heightMap, meshHeightMultiplier, meshHeightCurve, editorPreviewLOD),
    TextureGenerator.TextureFromColorMap(mapData.colorMap, mapChunkSize, mapChunkSize)
);

This means the terrain shape and the terrain appearance both come from the same generated data. The mesh uses the height values, while the texture uses the biome color map.

Chunks Instead of One Giant World

In a larger world, generating everything as one single object would not be practical. Because of that, the project uses chunks. The world is divided into separate terrain sections, and only the chunks around the viewer are created and updated. 

terrainChunkDictionary.Add(
    viewedChunkCoord,
    new TerrainChunk(viewedChunkCoord, chunkSize, detailLevels, transform, mapMaterial)
);

Each chunk can request its own map data, generate its own mesh, and display its own texture. This makes the world feel continuous, while internally it is built out of smaller manageable pieces.

Object Placement Based on Biomes

The generated biome data is also used for object placement. Decorations are not placed completely randomly. Instead, the system first checks which biome belongs to a tile, then reads the decoration layers linked to that biome, and only then decides what can spawn there. 

BiomeType biome = GetBiome(currentHeight, currentTemperature);

if (biome.decorationLayers == null || layerIndex >= biome.decorationLayers.Length)
{
    continue;
}

Additional rules can then be applied, such as spawn chance, sample interval, distance checks, and an extra noise threshold. This makes decoration placement depend on the generated world data, instead of just scattering objects everywhere.

Why This Matters

This step is where the project starts to feel like a real game development system. The generated maps are no longer just images for explanation, but the foundation for terrain generation, biome assignment, chunk loading, and decoration placement.

In other words, the same procedural data can now drive both how the world looks and how it is actually built inside Unity.

In the next step, the focus will move to the downside of this approach: once multiple data layers, chunks, meshes, and object placement are used together, generation becomes much heavier and performance starts to matter.
