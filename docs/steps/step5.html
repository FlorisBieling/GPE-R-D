Step 5: Biome classification and color preview

Rule-based selection

A biome is selected by testing the current height, temperature and moisture against configured min/max ranges. This configuration lives in the BiomeType[] biomes array in MapGenerator.

Biome data model

public struct BiomeType
{
    public string name;
    public BiomeTextureType textureType;
    public bool allowColorBlend;
    public float minHeight;
    public float maxHeight;
    public float minTemperature;
    public float maxTemperature;
    public float minMoisture;
    public float maxMoisture;
    public int priority;
    public Color color;
    public DecorationLayer[] decorationLayers;
}

Selection order

  1. Test every biome against all three value ranges.
  2. When ranges overlap, select the matching biome with the highest priority.
  3. When no range matches exactly, select the biome with the smallest total distance to its ranges.
  4. Use the selected biome color for editor previews and its texture type for shader weights.

The fallback prevents unconfigured gaps from turning magenta or leaving pixels without a biome. Priority makes deliberate overlaps possible, for example a narrow beach biome taking precedence over a broader plains range.

Why preview colors still exist

The final terrain is texture-based, but a simple color map remains valuable. It is cheap to inspect, easy to display in the editor and useful for debugging whether biome classification is correct before looking at the shader.

Optional color smoothing

BiomeGenerator can average neighbouring preview colors when both biomes allow blending. This only improves the generated color preview. The final texture transition is controlled separately by the control-map weights and the shader.

Why range-based biome data was chosen

Compared with hard-coded if-statements

Biome design remains editable data

Ranges, priorities, colors, texture types and decorations can be changed in the Inspector without rewriting the selection algorithm.

Compared with one biome enum per height band

Three dimensions create much more variation

Height, temperature and moisture can all influence the result, so similar elevations do not have to look identical.

Compared with requiring perfect range coverage

Priority and closest-range fallback keep generation robust

Priority supports intentional overlap, while fallback ensures every coordinate still receives a valid biome during experimentation.

Authoring improvement

A validation view would make the data easier to inspect

The current fallback is useful, but a future editor tool could visualise overlaps and uncovered combinations so the biome table is easier to verify.
