Conclusion, design reasoning and future work

Evaluation

The project demonstrates a well-connected procedural terrain pipeline rather than a collection of isolated experiments. Its strongest result is that each stage solves a different problem: noise creates continuous data, biome rules add meaning, control maps describe transitions, the shader creates the final surface and the runtime architecture keeps the world responsive around the viewer.

Answer to the research question

Coherent noise becomes practical terrain through a pipeline. Fractal noise supplies continuous values; height becomes geometry; temperature and moisture add classification dimensions; biome rules assign meaning; control maps carry blend weights; the custom URP shader turns those weights into a textured surface; and chunks, LOD, background calculation and gradual spawning keep the world interactive.

What is genuinely good about the system

  • Internal consistency: the same world data drives shape, classification, rendering and decoration.
  • Appropriate separation: dominant biomes handle logic while weighted control maps handle rendering transitions.
  • Data-driven authoring: biome ranges, priorities, textures and decoration layers can be changed without rewriting the algorithm.
  • Seamless terrain texturing: world-space sampling prevents the texture pattern from restarting at every chunk.
  • Scalable world structure: chunks and LOD concentrate generation and geometry around the viewer.
  • Safe Unity integration: calculation data is prepared away from the main thread and applied through queued callbacks.
  • Reproducibility: seeded maps and deterministic decoration decisions regenerate the same world consistently.
  • Maintainability: the former large generator is now divided into classes with focused responsibilities.

Why these choices were preferred over the alternatives

Procedural maps instead of authored world textures

Seeded maps support endless generation and do not require one enormous stored height or biome image.

Range-based biomes instead of nested hard-coded rules

The world design remains editable in data and can grow without turning the selection method into a long conditional block.

Control maps instead of one material per biome

Several textures can blend on the same chunk without adding submesh boundaries or changing materials across the terrain.

Custom HLSL instead of relying entirely on a ready-made material

The shader matches the exact seven-channel workflow, preserves world-space continuity and documents how the Asset Store textures are combined.

Most relevant area for improvement

The next decision should be based on profiling. The current system is technically sound, but target-hardware measurements should determine whether the first optimisation belongs in shader sampling, runtime resource reuse, thread scheduling or dense decoration rendering. This is a refinement of a working architecture rather than a replacement of the chosen approach.

Recommended future work, in priority order

1. Profile before rewriting

Measure CPU generation time, texture creation, fragment cost, memory growth and decoration spikes on the target hardware.

2. Refine shader performance when needed

Possible options include texture arrays, packed material maps, dominant-layer shortcuts or a smaller active texture set per terrain region.

3. Add slope-aware texturing

Triplanar mapping can be reserved for steep mountains while the current efficient planar mapping remains on flatter terrain.

4. Scale the scheduling model

Unity Jobs and Burst, Tasks with bounded concurrency or a thread pool become useful when the number of simultaneous chunk requests increases.

5. Reuse runtime resources

Pooling decorations and reusing per-chunk meshes, textures or materials can support longer sessions and denser worlds.

6. Expand authoring tools

Validated ScriptableObjects and a visual biome-range editor would make the existing data-driven workflow even easier to use.

Texture source and distribution choice

The albedo, normal and specular source textures were obtained from Yughues Free Ground Materials by Nobiax / Yughues through the Unity Asset Store. They were selected and recombined through a custom shader rather than redistributed as a new texture pack. The downloadable zip therefore contains project code and shader setup, but users must obtain the original textures through the official Asset Store package.
